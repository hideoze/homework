# CPU SpMM profiling：设计与验收方案

## 目标

不是“打印一堆性能计数器”，而是建立可验证链条：

```text
已知机制的正确 SpMM 样例
   ↓
A：先测干净参考性能，冻结答案与配置
   ↓
B：独立计时 + 每线程观测 + 编译指令证据 + 可选 PMU
   ↓
只改一个因素的探针 → 证据支持的原因与建议
   ↓
C：按建议重新运行原实现和优化实现
   ↓
判定：测量可复现？原因命中？数值正确？优化确实有效？
```

本版不需要 Agent。测量、状态判断与验收由确定性代码完成。以后接入 LLM 时，只让模型读取已结构化的证据并组织解释，不让模型“补出”缺失计数器。

## 1. 为什么不用一篇论文的固定毫秒数作为 A

绝对性能与 CPU、核数、频率、内存拓扑、编译器、线程运行时、矩阵、B 列宽、热身与计时边界有关。因此，A 分成三部分：

**机制真值**：通过可审查的代码对照知道故意改变了什么，例如只改变行的线程分配，或两侧都关闭向量化而只交换循环顺序。

**本机参考性能**：在当前硬件先采集原实现与修复版本的干净耗时。输入哈希、二进制哈希和运行配置一起保存。

**生效条件**：已知机制必须在本机造成可观测的差异，否则该样例为“不适用/未激活”，不能用它要求 profiler 必须诊断出一个不存在的主导瓶颈。

矩阵结构本身不是瓶颈标签。非均匀行长在合理调度下可能并不造成显著时间不平衡；局部性差也不自动等于带宽饱和。

## 2. 数据与数学语义

计算 C = A × B，A 为 CSR 稀疏矩阵，B/C 为行主序稠密矩阵，FP32，alpha=1，beta=0。m 是 A 的行数，k 是 A 的列数，n 是 B 的列数；非零元数为 nnz。

有效乘加工作量：

```text
FLOPs = 2 × nnz × n
GFLOP/s = FLOPs / (time_ms × 10^6)
```

这里是算法有效工作量，不是 PMU 测得的指令数；不包含索引计算和 C 清零的指令。C 清零的耗时仍包含在执行计时中。

每个输出元素独立使用 FP64 累加做正确性参考；检查：

```text
abs(C_test - C_ref) <= 1e-4 + 3e-4 × abs(C_ref)
```

这不是只检查 checksum。checksum 仅作额外记录。正式计时前后都会检查全输出。

## 3. 五类受控样例的因果解释

### C00：负对照

均匀行长、连续特征维、SIMD、单一并行区域。工具应能输出“没有足够证据支持当前已实现的缺陷类别”。“无已支持问题”不是“性能最优”。

### C01：向量化

核心循环 r → q → f 中，f 是 B/C 连续的特征维。关闭向量化的对象文件与显式 SIMD 对象文件使用相同输入和行分区。检查最终反汇编而不只检查源代码中有没有 pragma。

静态 packed 浮点指令存在不能量化动态 SIMD 利用率；不存在加上单因素 SIMD 变体稳定改善，才能对本样例形成有用证据。

### C02：循环顺序

原实现 r → f → q 在一个 f 上沿不规则稀疏索引读取 B。对照 r → q → f 连续遍历 B 的整段特征维。两侧都禁用自动向量化，尽量隔离循环顺序因素。

该实验支持“循环顺序敏感”，以及“优先测试连续特征维/分块”的方向；它不能单独判定具体是哪级缓存、TLB 或 DRAM 带宽限制。

### C03：线程负载不均

W_t = 分配给线程 t 的 nnz × n。

```text
I_work = max(W_t) / mean(W_t)
I_active = max(active_time_t) / mean(active_time_t)
```

I_work=1 表示工作量均匀。案例中前 1/8 行为其余行的 64 倍 nnz，按相同行数切分会导致某个线程承担大部分工作。按 nnz 前缀划分只改变行归属，不改变 row kernel。

I_active 包含被操作系统抢占的影响；必须结合 I_work 和改善实验，而不是单凭某个线程慢。

若只有一个超长行，按 nnz 划分完整行也无法解决，需要另做行内分段/归约，当前版本只给方向，没有实现这种变换。

### C04：并行粒度

每 16 行创建一个并行区域，2048 行需要 128 个区域。合并为一个区域保持同一行函数和相同输入，减少管理、唤醒和同步成本。

这定位的是“过细并行粒度的代价”，不是精确地量出了某一个 barrier 的等待时间。OpenMP wait policy 会影响绝对收益，必须保存运行环境。

## 4. 测量分层与边界

**环境层**：CPU 亲和性、报告的拓扑、cgroup 配额、虚拟化、编译器、二进制。

**执行层**：干净计时样本、中位数、相对 MAD、有效 GFLOP/s；setup/plan 独立记录。

**线程层**：实际行数/nnz、活跃 wall/CPU 时间、CPU 首尾位置、并行区域次数；检查所有线程之和等于总行数和总 nnz。

**指令层**：反汇编检查 packed/scalar 浮点指令；保留 GCC 向量化报告。

**硬件层（可选）**：每线程 perf_event_open，分 core/cache/branch 三组采集，保存事件原始值、缩放值和 time_enabled/time_running。

**干预层**：同输入单因素修复的性能变化，随后执行独立确认实验。

计时范围：

```text
不计时：读文件/生成矩阵 → 分配 → 建立线程分区 → 首次执行/正确性 → 热身
计时：  清零 C + 真正 SpMM + 线程区域进入/退出（多次重复）
不计时：再次正确性检查 → 生成报告
```

插桩和 PMU 使用另外的执行过程，不拿 profiler 增加的耗时当作原程序耗时。当前是热身后的重复调用，不是冷缓存或一次性端到端调用。

## 5. 不允许的诊断捷径

不能由“缓存缺失多”直接宣布 memory-bandwidth-bound。

不能把 `sizeof(CSR)+sizeof(B)+sizeof(C)` 除以时间叫作实测 DRAM 带宽；这只是存储占用，不包含真实重复读写、缓存命中、回写和写分配行为。

不能将通用 cache-misses 一律叫作 LLC misses。

不能以 CPU 使用率低单独断言算力未利用；线程同步、任务过小、操作系统调度与虚拟机配额都可能影响它。

不能将静态 SIMD 指令数量解释成动态 SIMD 利用率。

不能把 `wall time - active time` 直接叫作 barrier wait。

不能在缺失硬件事件时填零，不能把“不可用”当作“没有问题”。

## 6. 验收

本版将验收拆开，避免一个成功掩盖另一个失败：

| 检查 | 方法 |
|---|---|
| 数学正确 | 全输出与 FP64 参考逐元素比较 |
| 条件一致 | 输入、实现配置、环境、二进制身份一致 |
| 时间可复现 | A/B 偏差与各自相对 MAD 通过预设阈值 |
| 原因识别 | 诊断结果与未提供给诊断器的 oracle 比较 |
| 优化有效 | 新实验 C 中的单因素修复稳定改善 |
| 不乱报问题 | 正常负对照没有虚构诊断 |
| 不编造数据 | PMU 不可用时为空值并提供原因 |

A/B 默认偏差阈值 15%、相对 MAD 上限 10%。探针筛选要求至少 1.15×，C 默认三对独立实验中位数至少 1.15×且每对至少 1.05×。所有阈值都是此实验的工程选择；不能运行后为了让结果通过而调整。

如果诊断命中且优化有效，但 A/B 超出阈值，报告 `diagnosis_pass_timing_warning`，不算严格通过。

## 7. 如何从实验室过渡到真实程序

第一步，在实际 Linux CPU 主机重新执行随包五个样例，固定线程和亲和性；不要沿用当前容器的绝对耗时。

第二步，改变随机种子、尺寸、n、线程数，尤其加入未激活与混合原因样例。这个阶段不能只挑容易提速的输入。

第三步，用 SuiteSparse 等真实矩阵做留出测试。矩阵集合提供可复现输入，不提供适用于所有硬件的瓶颈标准答案。本工具支持 Matrix Market 输入，但当前发布结果没有把真实矩阵验证算进准确率。

第四步，增加 CPU oneMKL Sparse BLAS 的同语义 SpMM 适配器作外部性能参照。必须对齐线程、精度、布局、预处理复用次数和计时边界；不要把 vendor 库比自写代码快简单等同于某个具体原因。

第五步，硬件指标可用后再拓展：

- 内存带宽：平台专用内存控制器/uncore 事件得到 DRAM 字节数，配合同机/同线程/同 NUMA 策略的可持续带宽基线。报告 CPU 型号相关事件映射和归属限制。
- NUMA：对比绑定/first-touch 策略，量出实际放置和远程访问，不能只凭 CPU 型号推断。
- 缓存/局部性：多种工作集规模、重排、分块和相应事件的单因素实验。
- 伪共享：对比独立 cache-line 输出/元数据布局，并以支持的数据共享事件与改进实验佐证。
- 扩展性：对 1/2/4/... 线程执行相同输入；区分硬件带宽饱和、负载不均和系统配额。

这些是后续扩展条件，不是本版已经完成的能力。

## 8. 预处理成本不能永久忽略

本版的稳态执行计时排除了计划构造，并把 plan_ms 单独记录。若实际使用仅调用一次，必须比较：

```text
T_total(K) = T_setup + T_plan + K × T_execution
```

新方案有额外预处理时，收益成立的复用次数约为：

```text
K > extra_preprocessing_time / (old_execution_time - new_execution_time)
```

此处要求分母为正；实际判断应使用稳定测量，而不是两个几微秒 setup 值的噪声差。第一版未自动将该式作为投资回报判断，只暴露相应阶段数据。

## 9. 第一版的结论边界

随包 demo 中，五个受控样例的预期分类全部命中，四个缺陷的建议都经独立重新执行提速；严格验收四个通过，一个因为 A/B 计时波动告警。

该结果不等于对任意 CPU SpMM 有 100% 准确率；规则和样例针对同一组机制设计，仍需要新的输入、实现和硬件留出验证。PMU 在本次环境不可用，因此不能宣称已完成实际缓存、IPC、带宽或 NUMA 诊断。
